# Contract: a block's translatable texts, and how they cross to the model

**Owners**: the schema is `@endora-commerce/contracts` (`packages/contracts/src/cms.ts`); each
declaration is the block-owning module's (`manifest.blocks[].translatable`); extraction, encoding
and injection are `cms`' (`packages/modules/cms/src/backend/services/translation/`).

## 1. Declaration

```ts
export const translatablePathRe =
  /^[a-zA-Z][a-zA-Z0-9_]*(\[\])?(\.[a-zA-Z][a-zA-Z0-9_]*(\[\])?)*$/;

export const blockTranslatableTextSchema = z.object({
  path: z.string().regex(translatablePathRe).max(128),
  format: z.enum(['plain', 'tiptap', 'html']).optional(),
});

// BlockDefinitionSchema gains:
translatable: z.array(blockTranslatableTextSchema).max(32)
  .refine(uniquePaths, 'translatable paths must be unique')
  .optional(),
```

The same optional property is added to the component entries of `cmsPageBuilderDescriptorSchema`
(additive; a consumer that ignores it is unaffected). `PageBuilderRegistry.registerManifest` stores
it; `describe()` serves it; a new `translatableFor(name)` returns it for the translation service,
**after** the presence filter, so a block whose owner is switched off is "unknown".

Authoring rules (stated in `packages/modules/cms/docs/cms/extending-page-builder.md`):

1. Declare every prop that a shopper reads as prose; never a URL, slug, id, code, colour, icon,
   asset reference, HTML/script source, or `editorName`.
2. Do not declare slot props; child blocks declare their own.
3. `format: 'tiptap'` only for a prop holding a TipTap JSON document. A derived HTML prop beside it
   is regenerated by the block's own `resolveData` and is never declared.
4. `[]` is the declaration "no prose"; omit the property only for blocks that are not offered in the
   `cms` context.

## 2. Resolution

For a component node `{ type, props }` with declaration `D`:

- For each `{ path, format }` in `D`, walk `props` along `path`; `name[]` iterates an array (a
  non-array value yields nothing). A leaf is taken when it is a non-empty string (`plain`) or an
  object with a `content` array (`tiptap`); anything else is skipped silently.
- Then descend into every prop value that is an array of objects shaped `{ type: string, props:
  object }` (Puck slots), and into `data.zones[*]` for legacy zone content, and into `data.root.props`
  for the root (the CMS root declares nothing in this version).

## 3. Encoding of a `tiptap` leaf

Block-level nodes whose content is inline (`paragraph`, `heading`, and the paragraphs nested in
`bulletList`/`orderedList`/`listItem`/`blockquote`/`table*`) each become one segment of kind
`inline`:

- consecutive text nodes with the **same** mark list form a run; an unmarked run is emitted as is;
  a marked run is wrapped as `<n>…</n>` with `n` the index of its mark list in the segment's tag
  table;
- `hardBreak` becomes `<br/>`;
- any other inline node (e.g. an inline image) becomes a self-closing `<n/>` placeholder carrying the
  node verbatim in the tag table;
- the tag table (mark lists and opaque nodes, **including link `href`s**) stays on the server.

Decoding parses the returned string with a strict tokenizer (no nesting of the same `n`, every
opened tag closed, every tag of the source present exactly once, no unknown tag); on any violation
the segment is rejected (kept as source, counted untranslated). The rebuilt text nodes replace the
block-level node's `content`; the node's own `attrs` (heading level, alignment, …) are untouched.

`plain` leaves are sent as they are; a `plain` string containing `<` or `>` is escaped as `&lt;`/
`&gt;` on the way out and unescaped on the way back, so the tag syntax cannot be forged by content.

## 3a. Encoding of an `html` leaf (added during implementation)

An HTML string prop (`cms.Accordion` and `cms.Tabs` item content) becomes one segment in which
every tag is replaced by a self-closing `<n/>`, numbered in source order; the tags (including
`href`s) stay on the server. A stray `<` or `>` in text is escaped. The answer must return the
placeholders `0…n-1` **in the same order** — order is the only thing keeping an opening tag before
its closing one — and no other angle bracket; otherwise the segment keeps its original wording.

## 4. Placeholders

A `{{…}}` token (regex `/\{\{[^{}]{1,128}\}\}/g`) in a source segment must occur in the translation
the same number of times; otherwise the segment is rejected.

## 5. Model I/O

System prompt: research R16. User message: a JSON array `[{ "id": "s1", "text": "…" }, …]`.
Forced tool:

```json
{
  "name": "cms.submit_translations",
  "description": "Return the translation of every input segment, each id exactly once.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "translations": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": { "id": { "type": "string" }, "text": { "type": "string" } },
          "required": ["id", "text"]
        }
      }
    },
    "required": ["translations"]
  }
}
```

An id not in the chunk is ignored; a missing id or a duplicate id rejects that segment only.
